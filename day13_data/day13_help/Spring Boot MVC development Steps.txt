What is Spring Boot ?
- Yet Another module / framework/project from Spring Eco System (spring.io)
- RAD (Rapid Application development ) tool
- Accelarator for developing spring applications

Why 
1. Spring boot creates & populates automatically 
 - pom.xml 
 - Using the concept of Spring Boot Starters
1.1
Spring Boot Starters
 - Predefined collection of related dependencies
 - simplifies dependencies in pom.xml.
Eg. Spring boot web starter, data JPA starter , validation , security , cloud .....
The earlier efforts of identifying the dependencies required for the project  & matching their compatible versions
- is auto managed by spring boot.


2. Spring boot provides
- auto configuration support.
- Inherits the default configuration from spring boot starter parent

Eg - 
1. When you choose Spring Web starter 
- It will auto configure MVC blocks 
 - DispatcherServlet , HandlerMapping , ViewResolver 
- NO need of web.xml , spring-servlet.xml
2. When you choose Spring Data JPA starter
 - Configures auto DBCP (default DBCP Vendor - Hikari)
 (using application.properties | application.yaml) - <resources>
 - Configures JPA Entity Manager Factory (equivalent of SessionFactory)
 - Configures Transaction manager bean to support annotation based transactions
.....

3. Spring boot provides
- Embedded Tomcat container
 - to deploy web apps as well as  RESTful web service(backend)
- NO need of adding any external web server | application server.

Allows programmer to override these defaults 
- with additional dependencies (pom.xml)
- with additional configuration

4. Using Spring Boot Actuator  | Micrometer 
 - It exposes end points 
 - to check the health of the app
 - health of spring beans
 - auditing , profiling , monitoring of the app , in the producton phase becomes easier.

Summary 
Spring Boot = Spring Framework(D.I / IoC)
 + embedded Tomcat container 
 + auto configuration support
 - extensive xml configuration

8. Problem observed after porting earlier non spring boot application 
8.1 HibernateException -  No CurrentSessionContext configured
 - In DAO layer 
 sessionFactory.getCurrentSession
8.2 Cause
 -Spring Boot DOES NOT directly support Hibernate native APIs
 - org.hibernate.SessionFactory , Session , Transaction ....

8.3 Solution 
Abstract Hibernate by its Specification
- JPA (Java Persistentce API)
- In DAO layer 
Replace 
org.hibernate by jakarta.persistence(javax.persistence) - JPA
 SessionFactory by its super interface - EntityManagerFactory
Session  by its super interface - EntityManager

In Spring Boot based DAO layer
- replace ealier dependency of SessionFactory by 

@Autowired //spring annotation
private EntityManager manager;
OR 
@PersistenceContext //JPA annotation => L1 cache (session level cache)
private EntityManager manager;


8.4 IMPORTANT
Any DAO layer 
 - JDBC | Hibernate | JPA based , usually consists of repeatative requirements (CRUD)
Instead of developer taking efforts in DAO layer implementation, 

Enter 
Spring Data Framework
- Another popular framework , from Spring Eco system 
 - which simply sits over existing Spring framework.
- Supports  JDBC 
- Supports  JPA

Why ?
- Offers simplification of DAO layer
- Removes the need of writing DAO implementation classes 
- Only need to write DAO interfaces , extending from Spring Data APIs
- Offers consistent ,  stanadard & ready made implementation of JPA's EntityManager APIs.
- Complete reduction of boilerplate code.

Refer - day13_data\day13_help\Spring Data JPA\regarding spring data JPA.txt

Annotation in Spring web MVC 
@RequestParam 
- Method argument level annotation
- Binds incoming request parameter to method argument of request handling method.
- internally invokes request.getParameter -> parsing (if required)
- another example of IoC !

Equivalent Java code 
Long uid=Long.parseLong(request.getParameter("uid"));
 - view -> model data binding


Eg. http://localhost:8080/ems/emps/update?uid=1
@RequestParam("uid") Long uid1
SC 
Long uid1=Long.parseLong(request.getParameter("uid1"));
 - NullPointerException

Suggestion - Simply match request param name with method arg name.
